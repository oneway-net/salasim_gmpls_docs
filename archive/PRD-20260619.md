## 1. 产品概述

### 1.1 产品定位

SALASIM-GMPLS 是一个面向 LEO（低轨）卫星星座网络的 **层级化有状态 PCE 仿真平台**。它在 Kubernetes 集群上模拟完整的 GMPLS 控制平面（包含 H-PCE、域 PCE、OSPF-TE 拓扑分发、RSVP-TE 信令），同时结合轨道力学引擎生成时变拓扑，使研究人员和工程师能够在不依赖真实卫星硬件的前提下，系统性地测试多域多层路径建立、重路由策略及保护机制。

### 1.2 核心价值

| 价值 | 说明 |
|------|------|
| 协议完整性 | 完整实现 RFC 8231（有状态 PCE）、RFC 6805（H-PCE）、RFC 7699（SSON 频谱标签）、RFC 2205（RSVP-TE） |
| 时变拓扑 | 基于 Skyfield 轨道力学引擎自动生成帧序列，真实模拟 GSL/ISL 可见性切换 |
| 多层支持 | 同一仿真中同时运行 SSON（弹性光网格）、WSON（固定波长）、MPLS（带宽受限分组）业务 |
| 自动重路由 | 帧切换时预计算下一帧路径，拓扑变化后秒级完成 MBB 重路由 |
| 可观测性 | 全链路操作审计：INIT → REPLACING → ACTIVE/DOWN，带时间戳 ERO 历史与时延指标 |

### 1.3 目标用户

- **网络研究员**：验证跨域路径算法、频谱分配策略、卫星网络保护方案
- **协议工程师**：调试 PCEP/RSVP-TE/OSPF-TE 互通行为
- **系统集成商**：在上星前完整演练 GMPLS 控制平面集成
- **卫星运营商**：评估业务建立成功率与拓扑切换影响

## 3. 功能需求

### 3.1 星座定义与编译

#### F-01 Walker 星座生成
- 用户通过 API 或 UI 定义 Walker 星座参数（卫星数、轨道面数、相位因子、轨道高度、倾角）
- 系统调用 Skyfield 轨道力学引擎生成时序快照序列
- 每个快照包含：当前帧所有节点位置、可见 GSL 列表、ISL 拓扑图、链路度量（延时、带宽）
- 支持自定义地面站坐标（经纬度、仰角门限）

#### F-02 场景编译
- 输入：星座定义 + 仿真 Profile
- 输出：
  - Kubernetes manifests（Deployment / Service / ConfigMap / PVC）
  - 每帧 Parent/Domain 拓扑 JSON（含节点 `domainId` 映射，供 RM 初始化）
  - PCEServerConfiguration.xml（算法注册、OF 码映射）
  - 帧调度表 `schedule.json`（frameIndex → simTimeMs → topologyFile）
  - Emulator StatefulSet manifests（每节点一个 pod）

#### F-03 部署管理
- 一键部署（拉镜像、注入 artifact、滚动启动）
- 健康检查：PCEP 会话建立门控（所有域 PCE 完成 PCC 连接后才允许仿真启动）
- 支持滚动更新 PCE 镜像，emulator 自动重连（PCEP CLOSE 后 3s 重连）

---

### 3.2 仿真运行

#### F-04 仿真 Profile
用户可配置以下参数：

| 参数 | 说明 | 默认值 |
|------|------|--------|
| `startTime` | 仿真起始时刻（UTC） | 当前时间 |
| `stepSeconds` | 帧步长（s） | 300 |
| `speedup` | 实时比（N:1） | 3.0 |
| `enabledTypes` | 允许的交换类型集合 | `[SSON]` |
| `snapshotCapacity` | 快照缓冲容量（帧数） | 36 |

#### F-05 帧轮转（时变拓扑）
- Parent PCE `AutonomousClockThread` 每 500ms 轮询仿真时间
- 帧切换时原子更新 MDTEDB（inter-domain 图）
- 同时向所有子域 PCE 广播链路变化事件（`LinkChangeEvent` fanout）
- 子域 `AutonomousClockThread` 独立驱动域内 TED 轮转
- SSON：AURE 预计算 λ 图刷新；MPLS：IP 层图带宽覆盖

#### F-06 快照上传调度（两水位模型）
- **低水位**（lookahead）：触发批量上传
- **高水位**（capacity）：填满缓冲区为止
- 考虑 speedup 动态调整上传时机，防止帧缺失

---

### 3.3 路径计算

#### F-07 多域路径计算（H-PCE / BRPC）
- Parent PCE 使用 `MDHPCEMinNumberDomainsKSPAlgorithm`（K=4 域间路径）
- 同域请求：跳过 KSP，直接向单域 PCE 发 PCReq
- 跨域请求：KSP → 每域 PCReq（携带 OF 码）→ 域内 PCE 计算段 ERO → 组装完整 ERO
- OF 码传播：GENERIC_CHANNEL（MPLS 等）统一 `copyObjectiveFunction()` 到子域请求

#### F-08 域内路径计算
| 类型 | OF 码 | 算法 | 说明 |
|------|-------|------|------|
| SSON | 1002 | `AURE_SSON_algorithm` | 基于 λ 图的频谱感知路由 |
| WSON | 1001 | `AURE_Algorithm` | 固定波长路由 |
| MPLS | 1003 | `MPLS_MinTH_Algorithm` | 最短跳带宽约束路由（Dijkstra/Operacion2） |

#### F-09 预计算（Lookahead）
- `ParentPrecomputeWorker` 在当前帧推进时，并行计算 N+1 帧的备用 ERO
- 帧切换时优先使用预计算 ERO（零 BRPC 时延）
- FutureFrameTLV 传递给子域 PCE，使其在未来 TED 上计算段 ERO

---

### 3.4 业务建立

#### F-10 MPLS 业务
- 用户通过 API 或 UI 创建 MPLS LSP
- **必填**：`bandwidth_bps`（> 0）、`switchingType: "MPLS"`
- UI：业务类型选择器（SSON / WSON / MPLS 三按钮），选 MPLS 时带宽字段标红星
- 流程：`POST /api/v1/services` → Parent PCE `/api/v1/pce/md-lsps` → BRPC → PCEPInitiate → RSVP-TE

#### F-11 SSON 业务
- 必填：`numSlots`（频谱宽度 M）
- 流程同上，域 PCE 使用 AURE_SSON 分配连续频谱槽

#### F-12 WSON 业务
- 必填：波长通道参数
- 状态：基础路径计算可用，频谱资源跟踪待完善

#### F-13 RSVP-TE 信令
- 入口节点：`PATH` → 中间节点 `forwardRSVPpath()` → 出口节点 `RESV` → 逐跳返回
- MPLS：`getRSVPTEPathMessageFromPCEPResponse()`，ERO 剥头（第一跳为本节点）
- MBB（Make-Before-Break）：PCUpd → 新 LSP 建立后删旧 LSP

---

### 3.5 重路由

#### F-14 拓扑变化检测
- `ParentAutonomousClockThread.publishInterDomainDiff()`：比较相邻帧 inter-domain 链路集合差
- 消失链路（goneLinks）触发 `rerouteAffectedByInterDomainDiff()`

#### F-15 MD-LSP 重路由
- 检查 MD-LSP fullERO 中是否存在连续 IP 对属于 goneLinks（`eroContainsUndirectedIpv4Link`）
- 命中 → `rerouteMdLsp()`：
  1. 检查退避门控（backoff）
  2. 使用预计算 ERO 或实时 BRPC（携带存储的 OF 码 + 带宽）
  3. PCUpd 发送到各子域 PCE → 等待 PCRpt ACK（超时 30s）
  4. 成功：发 `REPLACING → ACTIVE` 事件；失败：`REPLACING → DOWN` + 退避

#### F-16 陈旧链路即时检测
- 服务注册进 LSPDB 后，立即扫描 fullERO 中的跨域 hop 对
- 若对应 inter-domain 链路已从当前 MDTEDB 消失（服务建立期间帧切换），**立即触发重路由**
- 解决：BRPC 计算使用 N 帧 MDTEDB 但 LSPDB 注册在 N+1 帧的竞争问题

#### F-17 事件推送
- `LspEventEmitter` 维护快照缓冲区（urgency bypass + debounce idle flush）
- `ParentAutonomousClockThread` 在每次帧切换后、每 10s 心跳、停止时 `flushNow()`
- 事件 POST 到 Backend `/api/v1/internal/lsp-events` → 写入 `service_ero_history`

---

### 3.6 ReachabilityManager

#### F-18 域映射初始化
- PCE 启动时读取 `parent_topology_*.json` 的 `nodes[]` 数组
- 每个节点的 `{"id": "10.64.0.47", "domainId": "172.31.0.1"}` 注册为 `/32` 主机路由
- **场景编译时**将所有 ~200 个卫星节点写入 `nodes[]`（包含边界节点和内部节点）
- BRPC 响应后动态学习：将子域 ERO 中的节点 IP 补充注册到 RM（兜底机制）

#### F-19 ERO 按域分段
- `splitEroByDomain()`：按 IP→domain 映射分割完整 ERO
- UnnumberIfIDEROSubobject（BRPC 域间标记）无法解析时直接跳过，不追加到前一域段

---

### 3.7 PCEP 会话管理

#### F-20 Emulator 自动重连
- PCEP CLOSE（PCE 优雅重启）后等待 3s 自动重连
- 仅 `stop()` 显式调用才永久停止重连循环
- DeadTimer：120s（检测 PCE 崩溃/网络中断）

#### F-21 PendingUpdateTracker
- SRP-ID 无符号掩码（防止负值误判）
- PCUpd ACK 匹配：ERO hop 字符串比对（前后各 ±1 跳容差）
- 超时（30s）触发告警，不阻塞主流程

---

### 3.8 可观测性与分析

#### F-22 ERO 历史
- 每条业务记录完整的操作历史：`INIT → REROUTE → ... → DOWN`
- 每条记录含：事件类型、原因、ERO hop 列表（统一 plain IP 格式）、快照索引、时间戳
- INIT 记录不要求 ERO 非空（无 ERO 的失败也记录）

#### F-23 时延指标
- **建立时延**：`POST /api/v1/services` 到首次 `ACTIVE` 的墙时时延
- **重路由时延**（atomic）：PCUpd 发送到最慢子域 PCRpt ACK 的时间
- **拆除时延**：PCUpd R=1 到 PCRpt(DOWN) 的时间
- 指标存储在 `pcep_latency_samples` 表，可按快照索引聚合

#### F-24 KPI 汇总
| KPI | 说明 |
|-----|------|
| 业务建立成功率 | completedOps / acceptedOps × 100% |
| ACTIVE 隧道数 | 当前 ACTIVE 状态的 tunnel 计数 |
| 重路由次数 | REROUTE 事件总数（按快照分布） |
| 平均建立时延 | setup latency 均值（ms） |
| 平均重路由时延 | reroute-atomic 均值（ms） |
| DOWN 隧道数 | 最终 DOWN 状态的 tunnel 计数 |

## 4. 非功能需求

### 4.1 性能
- 帧切换到完成所有受影响 LSP 检测：< 500ms
- 单域 BRPC（有预计算 ERO 命中）：< 50ms
- 单域 BRPC（无缓存，实时计算）：< 2s
- PCUpd 到 PCRpt ACK（正常 RSVP-TE 路径）：< 2s
- 支持 200 节点、4 域、100+ 并发 LSP

### 4.2 可靠性
- PCE 重启后 emulator 在 PCE 就绪后 30-60s 内自动恢复 PCEP 会话
- 场景编译生成的 RM 初始化数据覆盖所有 ~200 个卫星节点（无运行时 getDomain=null）
- MBB 失败时保持原 LSP 存活（Break-Before-Make 禁止）

### 4.3 可维护性
- 所有 `e.printStackTrace()` 替换为 `log.warn()`，无静默吞异常
- 影响正确性的 fallback（如 `num_slots=1` 兜底）移除，改为显式 NoPath
- ERO 历史记录格式统一（plain IP 字符串，跨 INIT/REROUTE/DOWN 一致）

### 4.4 部署
- 基于 MicroK8s，支持 `microk8s kubectl` 操作
- 本地 Docker registry（port 32000）
- PCE 一键重部署脚本（`redeploy-pce.sh`）：git pull → Maven build → docker push → rollout restart
- ClusterIP 从宿主机可达，DNS 不可从宿主机解析

## 6. 数据模型

### 6.1 核心实体（SQLite）

```sql
-- 仿真配置模板
simulation_profiles (id, name, layer_config_json, step_seconds, speedup, ...)

-- 部署实例
deployments (id, constellation_id, profile_id, metadata_json, ...)

-- 业务记录
services (id, deployment_id, simulator_run_id, src_node_id, dst_node_id,
          bandwidth_bps, switching_type, state, ...)

-- 隧道（每条业务可有 working/protection 多条隧道）
tunnels (id, service_id, role, symbolic_name, tunnel_id, ...)

-- ERO 历史（不可变事件流）
service_ero_history (id, service_id, simulator_run_id, event,
                     reason, snapshot_index, ero_json, created_at)

-- 异步操作追踪
operations (id, type, status, deployment_id, exit_code, result_json, ...)

-- PCEP 时延样本
pcep_latency_samples (id, kind, symbolic_path_name, reason,
                      latency_ms, snapshot_index, created_at)
```


## 10. 术语表

|------|------|

| PCEP | PCE Protocol，路径计算协议（RFC 8231 有状态扩展） |
| GMPLS | Generalized MPLS，广义多协议标签交换 |
| SSON | Spectrum-Switched Optical Network，频谱交换光网络（弹性光网格）|
| WSON | Wavelength Switched Optical Network，波长交换光网络 |
| MPLS | Multi-Protocol Label Switching，多协议标签交换 |
| TED | Traffic Engineering Database，流量工程数据库 |
| MDTEDB | Multi-Domain TEDB，多域 TED |
| ERO | Explicit Route Object，显式路由对象 |
| LSP | Label Switched Path，标签交换路径 |
| MD-LSP | Multi-Domain LSP，多域 LSP |
| RSVP-TE | Resource Reservation Protocol - Traffic Engineering |
| GSL | Ground-Space Link，地面-卫星链路 |
| ISL | Inter-Satellite Link，星间链路 |
